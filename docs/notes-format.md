# 注释格式与展示约定

[项目首页](../README.md) · [数据结构](data-format.md) · [内容审核与修订](review.md)

精选包的注释采用 `plain-notes-v1` 格式。JSON 字段仍为 `notes: string[]`；SQLite 表结构不变，运行库通过 `passages` 的 `kind='notes'` 读取。

## 条目规则

| 内容 | 格式与处理 |
|---|---|
| 词语释义 | `词语：解释。`，可明确区分的词条分别存放 |
| 相关词语或典故 | 可作为同一条目保留，不拆散完整解释 |
| 读音 | 优先附于词条，如 `绮（qǐ）窗：……`；无法附入时使用独立读音条目 |
| 异文 | 保留“一作”“又作”等版本说明 |
| 一般说明 | 使用 `说明：……` 或 `句意说明：……` |
| 原文引用 | 移除释义之前重复抄录的正文；解释所需的引文继续保留 |
| 纯原文占位 | 删除没有释义的正文条目，不以数组长度判定缺注 |

`notes` 为整篇注释列表，**不与 `content` 按下标对应**。没有难词的诗句可以没有单独注释；每篇作品仍须至少保留一项有效注释。格式统一不改变原有解释的学术审核状态。

## 实际示例

《杂诗三首·其二》的注释如下。原来的“君自故乡来，应知故乡事。”占位项已移除，第二句的词义与读音保留。

```json
{
  "notes": [
    "来日：来的时候。",
    "绮（qǐ）窗：雕画花纹的窗户。",
    "著（zhuó）花未：开花没有。",
    "著花：开花。",
    "未：用于句末，相当于“否”，表疑问。"
  ]
}
```

App 按数组顺序逐项展示即可，无须额外拼接正文或按正文行数补齐注释。运行库的读取 SQL 见 [有序段落查询](../app-runtime/README.md#列表与详情)。

## 整理范围与追溯

2026-11-11 整理全部 1524 篇作品，其中 1519 篇的注释数组发生变化。6589 个原条目拆分、清理为 20974 个展示条目；条目数增加主要来自拆分已有词义，并非新增同等数量的解释。整理后没有注释为空的作品。

正文、译文、赏析、作者资料、版本及 3389 组名句保持不变。另对《国风·鄘风·君子偕老》原来没有释义的“翟衣”据来源补释，该项单独标记为 `semantic_change=true`，依据保存在对应记录的 `evidence` 中。

| 位置 | 记录内容 |
|---|---|
| [raw/notes_normalization.json](../raw/notes_normalization.json) | 各篇整理前后数组、正文哈希、前后注释哈希、处理步骤、复核与补释依据 |
| `raw/review_resolutions.json` | 整理阶段与既有内容修订合成后的可重放结果 |
| `content_review.notes_normalization` | 版本、变更标记、前后哈希及记录位置 |
| `field_sources.notes.display_format` | `plain-notes-v1`；单纯格式调整保留原来源类型与模型 |
| 数据包 `manifest.notes_format` | 整包格式版本与 `document` 展示模式 |
| [整理验收报告](../reports/notes-normalization-audit.json) | 覆盖数、条目数、资料保留和双库一致性结果 |

原注释与既有审核输入均保留。修改正文或注释后，旧哈希不再匹配时编译会中止，须先更新显式整理记录，再按 [修订流程](review.md#修订流程) 重建和导出两种数据包。
